# 증권 계좌 통합 연동·포트폴리오 트래커 기획

> Read this when: 여러 증권사 계좌의 보유 종목·거래 내역을 한곳에 모으는 기능을 설계하거나 일정을 잡을 때. 결정 근거는 [ADR-106](decisions/106-account-aggregation-staged-sources.md)(Proposed), 제품 방향과의 관계는 [ADR-105](decisions/105-target-user-and-core-loop-redefinition.md)를 본다.
>
> 상태: **기획안 — 구현 전.** 2·3단계는 법률 자문([legal-review-brief.md §2-10·§2-12](legal-review-brief.md#2-12-여러-증권사-계좌를-한곳에-모아-보여주는-것이-마이데이터-허가-대상인가))이 나오기 전에는 만들지 않는다.

## 1. 결론

**지금은 없다.** 증권사 연동은 있지만 **주문을 내기 위한 연결**이다. 포트폴리오 기능은 **모의계좌 전용**이다.

| 항목 | 지금 | 근거 |
|---|---|---|
| 연동 증권사 | KIS·토스 2곳, BYOK(앱 키를 AES-256-GCM으로 암호화 저장) | `brokerage/domain/BrokerageAccount.kt`, ADR-015·026·027 |
| 사용자당 계좌 | **활성 계좌 1개** (`findByUserIdAndIsActiveTrue` → Optional) | 매뉴얼 §19 "한 번에 하나의 계좌만" |
| 가져오는 것 | 잔고·보유 종목을 **요청 때마다 조회, 저장 안 함**. monticker가 낸 주문의 체결·정산만 저장 | `BrokerageService.getBalance`, `brokerage_orders`·`brokerage_settlements` |
| 해외 계좌 | 없음 (토스 잔고는 KRW만 걸러냄, KIS는 국내 엔드포인트만) | `TossBrokerageClient` |
| 증권사 앱에서 직접 낸 매매 | 안 가져옴 — ADR-105가 "계획 밖 매매" 복기용으로 검토 중, 자문 전 보류 | legal-review-brief §1-7, §2-10 |
| 통합 포트폴리오 | 없음. `portfolio_positions`는 `paper_trades`에서 만든 모의계좌 읽기 모델(키 `user_id, stock_id`) | ADR-012, V21 |
| 수동 입력·CSV 가져오기 | 없음 (웹은 CSV **내보내기**만) | `apps/web/src/components/portfolio/csv.ts` |
| 수익률·배당·환율·세금 | 모의계좌 일간 수익률(ADR-091, 연쇄 TWR 아님)·실현손익만. 배당·환율·TWR/XIRR·국가·통화 배분·국내 세제 반영 없음 | `DailyReturnService`, `TaxHarvestingQueryService`(22% 고정) |
| 모바일 | 계좌·포트폴리오 화면 없음 (홈·알림·관심종목·종목) | `apps/mobile/src/app/` |

**제안:** "모든 증권 계좌"를 한 번에 약속하지 않는다. 데이터를 얻는 길을 단계로 나눈다.

1. **수동·CSV** — 법적 위험이 가장 낮다. 지금 바로 만들 수 있다.
2. **증권사 Open API 읽기 전용, 여러 계좌** — KIS·토스·키움·LS 등 API를 여는 곳만.
3. **마이데이터 경로** — 허가 취득 또는 허가 사업자와 제휴. 사실상 모든 증권사를 덮는 유일한 합법 경로다.

스크래핑은 쓰지 않는다. 그리고 이 기능은 독립된 "자산관리 앱"이 아니라 ADR-105 핵심 루프의 **재료**로 자리 잡는다.

## 2. 왜 만드나 — ADR-105와의 관계

ADR-105는 포트폴리오 최적화·세금 최적화를 **내렸다.** 그래서 "포트폴리오 앱 기능을 더 단다"를 그대로 따르면 방향과 어긋난다. 통합 보유 데이터가 핵심 루프에 들어가는 자리는 셋이다.

| 루프 단계 | 통합 보유가 하는 일 |
|---|---|
| 밤 — 계획 | 규칙(Watch Rule·조건부 주문·리스크 한도)을 **실제로 가진 종목 전체** 기준으로 세운다. 지금은 연동 계좌 1개만 보인다 |
| 낮 — 알림 | 피드·알림의 기준을 "관심종목"에서 **"내가 가진 종목(모든 계좌)"**으로 넓힌다. "보유 종목에서 무슨 일이 있었나"가 2025~2026년 홈 경쟁의 축이다([Robinhood Portfolio Digests](https://robinhood.com/us/en/newsroom/robinhood-presents-yes-no-event), 2025-12 — 보유 종목의 상승·하락 요인과 다가오는 이벤트를 투자 홈에 요약) |
| 저녁 — 복기 | 증권사 앱에서 직접 낸 매매까지 모아 **"계획 밖 매매"**로 보여준다(ADR-105 §5-3). 계좌가 여럿이면 우회 경로도 여럿이다 — 한 계좌만 보면 복기가 구멍 난다 |

그리고 ADR-105가 걱정한 **BYOK 부담**을 낮춘다. 키 발급 없이 CSV만으로도 가치를 먼저 준다.

## 3. 데이터를 얻는 길 비교

마이데이터 금융투자 업권 표준 API에는 포트폴리오 트래커에 필요한 것이 다 있다 ([금융보안원 API 규격](https://developers.mydatakorea.org/mdtb/apg/mac/bas/FSAG0402?id=4)).

| API | 얻는 것 |
|---|---|
| 금투-001 계좌 목록 | 계좌번호, 종류, 세제혜택 여부 |
| 금투-002 계좌 기본정보 | 예수금, 신용융자, 출금가능금액, 통화 |
| 금투-003 거래내역 | 종목, 일시, 거래 종류, 수량, 단가, 정산금액, 통화 |

그래서 **데이터 모델을 처음부터 이 모양에 맞춘다.** 1·2단계에서 쌓은 것이 3단계로 그대로 이어진다.

## 4. 기능 범위 — 포트폴리오 앱 기준

비교 대상: 토스증권·뱅크샐러드 같은 국내 통합 자산 화면, Sharesight·Snowball 같은 해외 트래커. 열 **"루프"**는 ADR-105 핵심 루프와 직접 이어지는지를 뜻한다.

| 우선 | 기능 | 루프 | 설명 |
|---|---|---|---|
| **MVP** | 계좌 목록 | ● | 계좌마다 출처(모의·API·CSV·수동·마이데이터)를 붙인다. 마지막 동기화 시각, 오류 상태(키 만료 등)를 보여준다 |
| MVP | 통합 보유 종목 | ● | 종목별로 합친 보기와 계좌별 보기. 수량, 평균단가, 평가금액, 평가손익, 비중 |
| MVP | 보유 기준 피드·알림 | ● | 기존 이벤트 감지·Watch Rule 대상에 "모든 계좌의 보유 종목"을 더한다. 신규 백엔드가 가장 적고 차별점이 가장 크다 |
| MVP | CSV·수동 가져오기 | ● | 미리보기 → 종목 매칭 확인 → 확정. 중복 행 방지(거래 지문). 되돌리기 가능 |
| P1 | 계획 밖 매매 | ● | 가져온 매매 중 monticker 규칙·주문과 연결되지 않은 것. 원장·감정 태그·준수율(ADR-091)에 합친다 |
| P1 | 수익률 | ○ | TWR(입출금 영향 제거)과 XIRR(내 돈 기준)을 함께 보여준다. 기간 선택. 벤치마크(KOSPI·S&P500) 비교 |
| P1 | 배당 | ○ | 받은 배당 내역, 예정 배당 캘린더(이벤트 타임라인에 배당락·지급일), 월별 배당, 투자금 대비 배당률 |
| P1 | 자산 배분 | ○ | 업종·국가·통화·자산군·계좌 종류(일반·ISA·연금) 기준. 쏠림 경고는 리스크 한도와 연결 |
| P1 | 환율 | ○ | 해외 종목의 원화 환산 평가금액, 환차손익과 주가 손익 분리 |
| P2 | 리밸런싱 연결 | ● | 기존 목표 비중(ADR-034)을 통합 보유 기준으로 계산. 주문은 지금처럼 연동 계좌에서만 |
| P2 | 세금 추정 | ○ | 해외주식 양도소득(연 250만 원 기본공제), 금융소득 종합과세 기준(연 2천만 원) 근접 알림. **최적화가 아니라 추정**이다(ADR-105가 내린 세금 최적화와 구분). 계산 규칙은 세무 확인 후 |
| 안 함 | 순자산(부동산·예금·코인), 가족 공유, 종목 추천 | — | 범위 밖. 추천은 투자자문업 인가 문제(legal-review-brief §2-7) |

## 5. 데이터 모델 (초안)

```text
portfolio_accounts        id, user_id, source(PAPER|BROKER_API|CSV|MANUAL|MYDATA), institution(KIS|TOSS|KIWOOM|...),
                          external_ref(계좌번호 마스킹·해시), account_kind(GENERAL|ISA|PENSION|IRP|...), base_currency,
                          brokerage_account_id NULL(주문용 연동과 연결), sync_status, last_synced_at, archived_at
portfolio_instruments     id, stock_id NULL, isin, exchange_code, local_code, name, asset_type, currency
                          — stocks에 없는 상품(펀드·채권·해외 ETF)과 매칭 대기 상태를 담는다
portfolio_transactions    id, account_id, instrument_id NULL(현금 거래), type(BUY|SELL|DIVIDEND|DEPOSIT|WITHDRAWAL|FEE|TAX|SPLIT|FX|TRANSFER_IN|OUT),
                          trade_date, settle_date, quantity, price, amount, fee, tax, currency, fx_rate,
                          source_ref, fingerprint(UNIQUE per account — 중복 가져오기 방지), import_batch_id
portfolio_holding_snapshots account_id, as_of, instrument_id, quantity, avg_cost, eval_amount, currency
                          — 증권사·마이데이터가 주는 "정답" 잔고. 거래로 다시 계산한 값과 대사한다
portfolio_import_batches  id, account_id, kind(CSV|API|MYDATA), file_hash, row_count, status, created_at, reverted_at
fx_rates_daily            date, currency, krw_rate, source
```

- **모의계좌는 옮기지 않는다.** 기존 `paper_trades`·`portfolio_positions`(ADR-012)를 `source=PAPER` 계좌로 **읽기 어댑터**만 둔다.
- **주문용 연동(`brokerage_accounts`)과 조회용 계좌를 분리한다.** 연결은 `brokerage_account_id`로만 한다. 지금의 "활성 1개" 제약은 주문 쪽에만 남긴다.
- **기준은 거래 원장이다.** 보유는 거래로 계산하고, 스냅샷과 매일 대사해 차이를 보여준다. CSV는 거래만 주고 API·마이데이터는 둘 다 준다.
- **평균단가 기준을 계좌마다 둔다.** 국내 증권사 표시는 대개 이동평균이다. 세금 계산 기준은 세무 확인 뒤 정한다.

## 6. 동기화·정합성

- **주기:** API·마이데이터는 장 마감 뒤 하루 1회 + 사용자가 당길 때. 장 초반·마감 직후는 피한다(마이데이터 규격도 그 시간대 거부 가능, 에러 50010).
- **대사:** 스냅샷 수량 ≠ 원장 계산 수량이면 "확인 필요"로 표시한다. 흔한 원인은 액면분할, 유상증자, 대체 입출고, CSV 누락 구간이다.
- **기업 행동:** 분할·병합·배당은 이벤트 감지(`stock_events`)와 연결해 자동 조정 후보를 낸다.
- **종목 매칭:** CSV의 종목명·코드 → `stocks`. 실패하면 `portfolio_instruments`에 매칭 대기로 두고, 사용자가 확인한다.
- **기존 실계좌 경로를 건드리지 않는다:** 리스크 검사·조건부 주문은 지금처럼 `getBalance` 실시간 조회를 쓴다. 통합 포트폴리오는 표시·복기용이다. 실거래 데이터 출처 불변식([ADR-055](decisions/055-price-provenance-gate-for-real-orders.md))과 섞지 않는다.

## 7. 보안·개인정보·법무

- **자격 증명:** 조회만 하는 연동에 주문 권한이 있는 키를 보관하는 것은 위험만 늘린다. 읽기 전용 권한을 주는 증권사는 그것만 받는다. 주지 않는 곳은 화면에 그렇게 밝힌다. 저장 방식은 기존 BYOK와 같다(AES-256-GCM, 해지 시 삭제 — ADR-067).
- **동의:** "계좌 정보 수집·이용" 동의 그룹을 따로 둔다(ADR-068 동의 기록). 목적, 항목, 보관 기간, 철회 방법을 적는다. 철회하면 가져온 거래도 지운다.
- **최소 수집:** 계좌번호는 마스킹·해시만 저장한다. CSV 원본 파일은 파싱 뒤 저장하지 않는다(해시만).
- **법무:** §2-10(체결 내역 저장)에 더해 **여러 계좌를 모으는 것 자체**를 새 질문 §2-12로 추가했다. 2단계는 그 답을 받은 뒤에 시작한다. 3단계 제휴는 제휴사 계약 구조까지 함께 본다.

## 8. 화면

- **웹:** 기존 `portfolio/`(모의)와 `brokerage/`(실계좌 대시보드)를 하나의 **"내 자산"**으로 묶는다. 계좌 전환 탭은 [통합 | 계좌별 | 모의]. 모의는 계좌 모드로 둔다(reports의 결론과 같은 방향).
- **모바일:** 4탭안의 "내 계좌" 탭이 통합 보유의 첫 자리다. 피드 상단의 작은 자산 요약과 보유 종목 이벤트 카드도 같은 데이터를 쓴다.

## 10. 정해야 할 것 (사용자 결정)

1. **이 기능을 ADR-105 루프의 재료로 둘지, 독립 축(자산 관리 앱)으로 키울지.** 이 문서는 전자를 전제로 우선순위를 매겼다. 후자라면 수익률·배당·배분이 MVP로 올라온다.
2. **1단계 시작 여부.** 자문 없이 할 수 있는 범위(수동·CSV·보유 기준 피드)만 먼저 할지.
3. **3단계 방향.** 허가 취득(비용·기간 큼)과 제휴(수수료, 제휴사 의존) 중 어느 쪽을 알아볼지. 어느 쪽이든 사업 판단이 먼저다.
4. **ADR-105 인터뷰에 질문을 더할지.** 예: "증권 계좌가 몇 개인가, 어디에 있나", "보유 종목을 한곳에서 보려고 지금 무엇을 쓰나". 2단계의 가치를 가장 싸게 검증하는 방법이다.
