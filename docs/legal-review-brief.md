# monticker — 법률 자문 요청 브리핑

> Read this when: 실제 변호사/법무 자문을 받기 전에 준비 자료가 필요할 때.

## 이 문서의 성격 — 반드시 읽을 것

**이 문서는 법률 자문이 아니다.** 나(Claude)는 변호사가 아니고, 이 문서의 어떤 문장도 법적 결론으로
취급해서는 안 된다. 이 문서의 목적은 딱 하나 — 실제 변호사에게 자문을 구할 때 매번 서비스 구조를
처음부터 설명하지 않아도 되도록, **사실관계**(코드가 실제로 무엇을 하는지)와 **질문 목록**을 미리
정리해 두는 것이다. [docs/launch-plan.md](launch-plan.md) Phase 1의 법률 검토 항목들은 이 브리핑을
자문 자료로 들고 간 뒤에도 여전히 "미완료"로 남아 있다 — 실제 자문 결과가 나오기 전까지는.

## 1. 서비스가 실제로 하는 일 (사실관계 — 변호사가 검증 가능하도록 코드 위치 첨부)

### 1-1. 모의투자 (기존 서비스, 이미 운영 중)
가상의 자금(초기 1,000만원)으로 실제 시장 데이터를 기반으로 매매를 체험한다. 실제 금전 이동이
전혀 없다. 근거: `backend/api/.../paper/`, `matching/` 모듈 전체.

### 1-2. 증권사 연동 (BYOK — 상용화 로드맵, 아직 미출시)
- 이용자가 **본인 명의로 개설한** 증권사(KIS/토스증권) 계좌의 Open API 키(appKey/appSecret)를
  직접 발급받아 등록한다. 회사가 대신 계좌를 개설하거나 자금을 예치하지 않는다.
- 등록된 키는 `BrokerageAccount.accessToken`에 AES-256-GCM으로 암호화 저장된다
  (`backend/api/.../common/security/EncryptedStringConverter.kt`).
- 회사는 `BrokerageClient` 인터페이스(`backend/api/.../brokerage/infrastructure/BrokerageClient.kt`)를
  통해 그 키로 증권사 API를 호출할 뿐이며, 주문 체결·정산은 전적으로 증권사 시스템에서 처리된다.
- 회사 명의의 통합 계좌나 예치금은 존재하지 않는다.

### 1-3. 결제 (구독·전략 마켓)
- 구독료·전략 마켓 판매 대금은 전자결제대행사(PG사, 토스페이먼츠)를 통해 처리된다
  (`docs/deployment.md` §2, `application-prod.yml`의 `TOSS_SECRET_KEY`).
- 크리에이터(전략 판매자) 수익 정산 로직이 존재한다 ([ADR-016](decisions/016-subscription-creator-revenue-sharing.md), `docs/settlement.md` §②).

### 1-4. Quant Lab / 전략 마켓
- 이용자가 만든 매매 규칙(룰셋)은 서버 사이드에서만 실행되며, 원문은 구매자·제3자에게 노출되지
  않는다. 구매자는 "신호"만 구독한다.
- 판매자는 수익률 보장·손실 보전 표현을 금지당하며, 모든 전략 카드에 "과거 성과가 미래 수익을
  보장하지 않는다"는 고지가 함께 노출된다.
- 이 설계의 제품적 근거: [docs/domain/quant-lab-positioning.md](domain/quant-lab-positioning.md) —
  "유사투자자문업과 어떻게 선을 긋는가"를 다룬 문서. **다만 이 문서는 제품 설계 관점의 근거이지,
  실제로 신고 의무가 없다는 법률적 결론이 아니다** — 아래 §2-2 참고.

### 1-5. AI 기능
- 뉴스·공시 텍스트 일부를 Anthropic(해외 사업자) API로 전송해 요약을 생성한다
  (`backend/api/.../ai/StockSummaryService.kt`).
- 시스템 프롬프트에 "투자 조언은 하지 말고, 사실 기반으로만 설명하라"는 지시가 명시되어 있다.
- 이용자의 개인 식별 정보(이름, 이메일 등)는 전송하지 않는다 — 전송되는 것은 종목명·뉴스 본문·가격
  데이터뿐이다.

## 2. 법률 자문이 필요한 구체 질문 (launch-plan.md Phase 1과 1:1 대응)

실제 자문 시 아래 순서·문구를 그대로 질문지로 사용할 수 있도록 정리했다.

### 2-1. 증권사 연동(BYOK)이 투자중개업 인가 대상인가?
> "이용자가 본인 명의 증권사 계좌의 Open API 키를 직접 등록하고, 회사는 그 키로 이용자를 대신해
> 증권사 API를 호출하기만 하며, 회사 명의의 예치금이나 통합 계좌를 운용하지 않는 구조입니다.
> 이 구조가 자본시장법상 투자중개업 인가 없이 운영 가능한지, 만약 조건부로 가능하다면 그 조건은
> 무엇인지 확인이 필요합니다."

### 2-2. Quant Lab / 전략 마켓이 유사투자자문업 신고 대상인가?
> "이용자가 만든 매매 규칙의 백테스트·실시간 신호를 다른 이용자가 유료로 구독하는 서비스입니다.
> 판매자는 원문을 공개하지 않고 신호만 제공하며, 수익률 보장 표현은 금지하고 위험 고지를 상시
> 노출합니다. 이 구조가 자본시장법상 유사투자자문업 신고 대상인지, 신고 대상이라면 어떤 절차가
> 필요한지 확인이 필요합니다."

### 2-3. 전자금융거래법 — 결제·정산 구조에 회사 자체 라이선스가 필요한가?
> "구독료·전략 마켓 판매 대금은 등록된 전자결제대행사(PG사)를 통해서만 처리하며, 회사가 직접
> 자금을 수납·보관하지 않습니다. 크리에이터에게 지급하는 수익 정산도 PG사 결제 이후 내부 원장
> 처리로 이루어집니다. 이 구조에 전자금융거래법상 별도 등록(전자금융업 등)이 필요한지 확인이
> 필요합니다."

### 2-4. 이용약관·개인정보처리방침 문구의 법적 충분성
> "[/terms](../apps/web/src/app/terms/page.tsx)와 [/privacy](../apps/web/src/app/privacy/page.tsx)에
> 초안을 게시했습니다. 특히 제5·6·11조(모의투자 성격, 증권사 연동, 면책)의 문구가 실제 법적
> 면책으로 충분한지, 환불 정책(제8조)이 전자상거래법 기준을 충족하는지 검토가 필요합니다."

### 2-5. 개인정보 국외 이전 고지
> "뉴스·공시 텍스트를 Anthropic(해외 사업자)에 전송해 AI 요약을 생성합니다. 개인 식별 정보는
> 전송하지 않지만, 개인정보 보호법상 국외 이전 고지 의무가 발생하는지 확인이 필요합니다."

### 2-6. 통신판매업 신고 필요 여부
> "구독형 유료 서비스와 전략 마켓(디지털 상품 판매)을 운영할 예정입니다. 통신판매업 신고 대상인지,
> 대상이라면 사업자 등록과 신고 중 무엇을 먼저 해야 하는지 확인이 필요합니다."

## 3. 사업자 등록 — 일반 절차 정보 (참고용, 최종 선택은 세무사·법무사 상담 권장)

아래는 한국에서 사업자를 등록하는 **일반적인 절차에 대한 공개 정보**이며, 이 프로젝트에 특정
형태를 권고하는 것이 아니다. 개인사업자/법인 중 어느 쪽이 적합한지는 지분 구조·투자 유치 계획·
세무 상황에 따라 달라지므로 세무사·법무사 상담이 필요하다.

| | 개인사업자 | 법인(주식회사) |
|---|---|---|
| 설립 절차 | 세무서/홈택스 사업자등록만으로 가능 | 정관 작성 → 법인 설립등기 → 사업자등록 |
| 책임 범위 | 무한책임(대표 개인 재산까지) | 유한책임(원칙적으로 출자금 한도) |
| 초기 비용/행정 부담 | 낮음 | 상대적으로 높음(등기 비용, 법인세 신고 등) |
| 투자 유치 | 지분 발행 불가 | 지분 발행 가능 |

**일반적인 절차 개요** (실제 진행 전 최신 절차를 각 공식 사이트에서 재확인):

1. **사업자등록**: 홈택스(hometax.go.kr) 또는 관할 세무서에서 사업자등록 신청. 업종 코드는
   서비스 성격(소프트웨어 개발·정보서비스 등)에 맞춰 세무서 상담 후 결정.
2. **통신판매업 신고**: 온라인으로 유료 서비스·상품을 판매하는 경우, 사업자등록 이후 관할
   구청/시청 또는 정부24(gov.kr)에서 통신판매업 신고. 결제대행사(PG) 계약 시 통신판매업
   신고증을 요구하는 경우가 많다.
3. **PG사 계약**: 토스페이먼츠 등 PG사와의 정식 계약은 사업자등록증(및 필요시 통신판매업
   신고증)을 전제로 한다 — `docs/deployment.md` §2가 이미 다루는 절차의 전제조건이다.

## 4. 자문 결과 반영 방법

법률 자문 결과가 나오면:
1. 이 문서의 §2 각 질문 아래에 자문 결과 요약을 추가한다 (자문 기관·일자와 함께).
2. `/terms`, `/privacy`의 주황색 표시 항목을 확정된 값으로 교체하고 초안 배너를 제거한다.
3. [docs/launch-plan.md](launch-plan.md) Phase 1의 해당 체크박스를 완료 처리한다.
4. 만약 자문 결과가 현재 구조(BYOK, PG 위탁 등)의 변경을 요구하면, 그 변경은 설계 결정이므로
   CLAUDE.md 기준에 따라 새 ADR로 기록한다.
