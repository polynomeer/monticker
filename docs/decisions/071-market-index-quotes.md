# ADR-071: 지수·환율 시세 수집 — 공급자 인터페이스 뒤의 Mock, 모의 여부를 행마다 기록

## Status
Accepted

## Context

터미널 디자인 시안(ADR-066)의 홈 화면에는 KOSPI·KOSDAQ·USD/KRW 카드와 상단 지수 스탯이 있고, /compare에는 "베타(KOSPI)"가 있다. 지금까지 지수·환율 데이터가 저장소 어디에도 없어 모두 `—`였다(docs/design-rollout-plan.md §2).

필요한 것은 두 가지다.

1. **최신 시세** — 홈 카드·상단 스탯(값, 전일 대비, 시각)
2. **일별 종가 이력** — 베타 계산(종목 일간 수익률과 지수 일간 수익률의 공분산), 카드 스파크라인

고려한 출처:

- **KIS 업종지수 API** — external-apis.md는 "KIS에 시장 지수 API가 있다"고만 적고, 엔드포인트·tr_id·응답 필드는 저장소 어디에도 없다. `KisClient`는 종목 현재가(`inquire-price`)와 투자자 동향만 구현돼 있고, 그 필드조차 "실제 KIS 키로 미검증"이라고 주석이 달려 있다(ADR-018). 규격을 확인하지 않은 채 필드 이름을 짐작해 구현하면, 응답이 어긋날 때 조용히 0이나 null이 실시세처럼 저장된다.
- **환율** — KIS 국내 시세 API에는 원/달러 환율이 없다. Toss Open API 목록에는 환율이 있지만 저장소의 Toss 클라이언트는 BYOK 주문용과 실시간 체결가용뿐이다.
- **KRX 정보데이터시스템** — 지수 이력은 있으나 T+1 EOD라 장중 카드에는 못 쓰고, 클라이언트도 없다.

수집 위치도 정해야 했다. 종목 시세·펀더멘털·투자자 동향 수집기는 모두 worker에 있고 api는 읽기만 한다.

## Decision

1. **worker에 공급자 인터페이스 `MarketIndexProvider`를 두고, 지금은 `MockMarketIndexProvider`만 구현한다.** 코드는 `KOSPI`·`KOSDAQ`·`USDKRW` 세 개(`MarketIndexCode`). 공급자는 `market-index.provider`(기본 `mock`)로 고르고, **모르는 값이면 기동을 실패시킨다** — `kis`를 기대하고 설정했는데 조용히 Mock으로 도는 일이 없게 한다.
2. **`MarketIndexCollector`(30초, `@DistributedLock`)** 가 공급자 값을 받아
   - `market_index_quotes`(지수별 최신 한 행: 값·전일 종가·시각·출처·`is_mocked`)를 upsert하고
   - `market_index_daily`(KST 거래일별 종가)의 당일 행을 최신 값으로 덮어쓴다. 장 마감 뒤 마지막 값이 그날 종가로 남는다(ADR-021의 일봉 실시간 upsert와 같은 방식).
   - 전일 종가는 `market_index_daily`에서 당일 이전 가장 최근 행으로 계산한다. 공급자가 전일 종가를 주지 않아도 된다.
   - 일봉 테이블이 비어 있으면 공급자 이력으로 한 번 채운다(Mock은 300거래일 모의 이력, 이력이 없는 공급자는 건너뜀).
3. **모든 행에 `source`·`is_mocked`를 저장하고 API가 그대로 내려준다.** 화면은 `isMocked=true` 값에 "모의" 표식을 붙이고, 상단 스탯 라벨에도 "(모의)"를 붙인다. 지어낸 숫자를 실데이터처럼 보여주지 않는다는 원칙(design-rollout-plan)을 지키면서도, 개발 환경에서 카드·베타 화면이 실제로 동작하는지 확인할 수 있다. `stock_fundamentals.is_mocked`(ADR-018)와 같은 패턴이다.
4. **api는 읽기만 한다.** `GET /api/market/indices`(최신 시세 + 최근 30거래일 종가)와 `GET /api/market/indices/{code}/daily?from&to`(최대 800행). 둘 다 비로그인 공개. 코드는 화이트리스트로만 받는다.
5. Mock은 국내 장 시간(`MarketSchedule` KOSPI 기준)에만 값을 움직인다. 장이 닫히면 새 값을 내지 않아 마지막 값이 유지된다.

## Reasons

- **규격을 모르는 실시세 연동보다 정직한 Mock이 낫다.** 실키로 검증하지 않은 필드 매핑은 "그럴듯한 오답"을 실시세로 저장할 위험이 있다. 인터페이스를 먼저 고정해 두면 실시세 공급자는 이 인터페이스 구현 하나와 설정 값 하나로 붙는다 — 테이블·API·화면은 바뀌지 않는다.
- **`is_mocked`를 행 단위로 두는 이유**: 공급자를 바꾸는 시점에 과거 일봉은 Mock, 새 일봉은 실시세가 섞인다. 베타처럼 이력을 쓰는 화면이 "이 계산에 모의 값이 섞였는지" 알 수 있어야 한다(`/daily` 응답에 행마다 `isMocked`가 있다).
- **전일 종가를 일봉 테이블에서 계산하는 이유**: 공급자마다 전일 종가 제공 여부가 다르다. 한 곳에서 계산하면 공급자 교체가 등락률 정의를 바꾸지 않는다.
- **worker에서 수집하는 이유**: 다른 시세 수집기와 같은 자리이고, `@DistributedLock`으로 레플리카가 여럿이어도 한 번만 돈다. api가 외부 시세를 직접 부르면 요청마다 외부 호출이 생기고 rate limit을 공유하게 된다.

## Consequences

- **운영에서도 실시세 공급자가 붙기 전까지 지수·환율은 Mock이다.** 화면에 "모의"가 계속 보인다. 실서비스 전에는 공급자 구현이 필요하다(아래 Revisit).
- 베타(KOSPI)는 지금 Mock 지수 기준이라 숫자에 의미가 없다 — /compare는 이 경우 "모의 지수 기준"이라고 표시한다.
- 휴장일 캘린더가 없어 Mock은 평일 공휴일에도 값을 움직이고 일봉을 만든다. 실시세 공급자는 휴장일에 값을 주지 않으므로 문제가 줄어든다.
- 공급자를 Mock에서 실시세로 바꿀 때 Mock 일봉 이력이 남는다. 바꾸는 시점에 `market_index_daily`에서 `is_mocked=true` 행을 지우고 실이력으로 다시 채우는 절차가 필요하다.

## Revisit When

- KIS 업종지수 API(또는 다른 지수 공급자)의 요청·응답 규격을 실제 키로 확인했을 때 — `MarketIndexProvider` 구현을 추가하고 `market-index.provider`에 값을 늘린다. 환율 출처도 함께 정한다.
- 휴장일 캘린더 API가 생겼을 때 — Mock과 수집기가 휴장일을 건너뛰게 한다.
- 지수가 3개보다 많아지거나(업종지수·해외 지수) 장중 분봉 차트가 필요해질 때 — 최신 한 행 + 일봉 구조로는 부족하다.
