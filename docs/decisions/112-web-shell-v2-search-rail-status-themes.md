# ADR-112: 웹 셸 2판 — 상단 고정 검색, 라벨 레일, 상태 알약, 주황은 실전 전용, 드라큘라 기본 테마

## Status
Accepted

[ADR-066](066-terminal-ui-shell.md)의 셸 결정 가운데 상단 바·아이콘 레일·계좌 칩·다크 전용을 바꾼다. 공통 키트(`components/terminal/`)와
페이지가 `TerminalPage`로 스스로를 감싸는 구조는 그대로다. 레일에서 "포트폴리오" 자리를 "내 자산"이 잇고 실전투자는 따로 둔다는
[ADR-110](110-assets-hub-absorbs-paper-portfolio.md)의 결정을 따른다.

## Context

2026-10 웹 디자인 시안 리뷰(디자인 캔버스 "monticker 디자인 시안" v18, 리뷰 원문은 [web-design-v2-plan.md](../web-design-v2-plan.md) §1)에서
셸에 다음 문제가 나왔다.

- **검색이 이동이다.** 상단 검색 알약은 `/stocks/search`로 가는 링크다. 레일의 "트레이딩"도 같은 검색 화면으로 간다. 홈에만 알약이 있고,
  다른 화면은 ⌘K를 알아야 검색할 수 있다.
- **상단 바가 두 줄이 된다.** `flex-wrap`이라 지표가 많은 화면(종목 상세 7개, 포트폴리오 6개)은 지표가 두 줄로 접힌다. 실전 주문 화면은
  계좌 칩·알림이 아랫줄로 밀린다.
- **레일이 아이콘 12개뿐이다.** 라벨이 없고, 알림·설정이 레일·헤더·계정 메뉴에 겹쳐 있다.
- **모의/실전 구분이 7px 점 하나다.** 노란 점과 주황 점의 대비가 1.52:1이다. 칩에 잔액이 늘 떠 있어 iOS 방향(상시 잔고 없음, 진행 중인 것만)과 다르다.
- **주황이 여러 뜻이다.** 실전 계좌 칩, 공시 이벤트, 경고·주의, 대기 상태, 색약 테마의 하락색에 모두 `dracula-orange`를 쓴다. "주황 = 실제 돈"이라는
  신호가 약해진다.
- **다크 전용.** 시안에서 테마 6종을 비교한 결과 기본은 드라큘라로 두고, 다른 테마를 고를 수 있게 하기로 했다.

고려한 대안:

1. **현 셸 유지, 시각만 손질.** 변경이 작지만 검색·레일·주황 문제는 구조 문제라 남는다.
2. **iOS처럼 하단·좌측 3탭(홈·관심종목·내 계좌)으로 축소.** 데스크톱 고급 기능(퀀트랩·전략 마켓·실전 주문)이 2단 깊이로 숨는다.
3. **라벨 레일 + 섹션 탭 + 상단 고정 검색 + 상태 알약** — 채택.

## Decision

### 상단 바

- 한 줄, 높이 56px, 줄바꿈 없음. 순서: 로고 · 검색 · 제목(또는 종목) · 지표 · (오른쪽 끝) 레이아웃 · 상태 알약 · 알림 · 계정.
- **검색은 모든 화면 상단에 고정된 입력창**이다(`role="combobox"`). 입력하면 그 자리에서 종목·이벤트·전략 미리보기가 열리고, Enter·항목 선택은
  바로 해당 화면으로 간다. "전체 결과"만 `/stocks/search`로 간다. ⌘K는 이 입력창에 포커스를 준다.
- 지표는 들어가는 만큼 한 줄로 보이고, 넘치면 "+N 지표" 버튼 하나로 접는다(우선순위 순으로 앞에서부터). 지금 화면 구성(최대 7개)은 1440px에서
  접지 않고 모두 들어간다.
- 종목 화면의 종목 선택 버튼(`SymbolPill`)에서 돋보기와 ⌘K 표시를 뺀다 — 검색은 상단 입력창 하나다.

### 레일

- 아이콘 + 라벨. 항목은 홈 · 관심종목 · 탐색 · 내 자산 · 실전투자 | 퀀트랩 · 전략 마켓 | (맨 아래) 설정.
- "트레이딩"(검색 화면 링크)과 "알림"(헤더 종으로 감)을 뺀다. 헤더의 "전체 메뉴"도 뺀다.
- 묶인 화면은 본문 맨 위 **섹션 탭**으로 오간다. 예: 탐색 = 스크리너 · 종목 비교, 퀀트랩 = 내 전략 · 룰셋 빌더 · 백테스트 · 포트폴리오 분석,
  실전투자 = 계좌 · 주문 · 조건부 주문 · 리밸런싱, 설정 = 화면 · 알림 · 구독 · 증권사 연동. 내 자산의 탭은 ADR-110의 통합 | 계좌별 | 모의투자를 그대로 쓴다.
- 활성 판정은 지금처럼 가장 긴 경로 일치다.

### 상태 알약 (계좌 칩 대체)

- 잔액을 상시 표시하지 않는다. 모드 배지(모의 / 실전) + 지금 진행 중인 것(실행 중 전략 수, 미체결 주문 수)만 짧게 보인다. 자세한 내용은 펼침 메뉴와
  `aria-label`에 둔다.
- 실전 화면(`account={{ kind: "live" }}`)은 배지와 테두리를 주황으로, 상단 바 위쪽에 주황 줄을 두른다.

### 색 역할

- **주황은 실전(실제 돈) 전용이다.** 실전 배지·실전 경고·실주문 확인에만 쓴다.
- 공시는 청록, 경고·주의·대기 상태는 노랑으로 옮긴다(회색은 이미 취소·만료라 대기까지 회색이면 구분되지 않는다). 공시와 같던 뉴스는 보조 회색으로 뗀다. 색약 테마의 하락색은 주황 대신 자홍으로 바꾸고 ▲▼ 기호를 늘 함께 쓴다.
- 강조색(보라)은 선택·포커스·주요 버튼 하나에 쓴다.

### 테마

- 표면·글자·강조·의미 색 토큰을 CSS 변수로 바꾼다(`--tm-page` 등, Tailwind 클래스 이름은 그대로). 테마는 `html[data-theme]`로 고른다.
- **기본은 드라큘라(지금 팔레트).** 그래파이트·미드나이트 네이비·클린 라이트·웜 페이퍼·하이 콘트라스트를 설정 › 화면에서 고를 수 있다.
  라이트 계열은 상승 빨강·하락 파랑이 기본값이고, 상승·하락 색 설정이 그 위에 덮인다.
- 캔버스 차트처럼 클래스를 못 쓰는 곳은 테마 토큰을 런타임에 읽는 함수로 색을 받는다.

## Reasons

- 검색은 증권 앱에서 가장 자주 쓰는 진입로다. 입력창이 늘 같은 자리에 있으면 화면 이동 없이 찾고 바로 들어간다. 검색 화면으로 가는 레일 항목은
  같은 길이 두 개라 지운다.
- 라벨이 있으면 처음 쓰는 사람도 레일을 읽을 수 있다. 섹션 탭으로 하위 화면을 모으면 레일이 8개로 줄어도 모든 화면이 두 번 안에 닿는다.
- "주황 = 실제 돈"을 단일 의미로 지키면 실전 화면 혼동(ADR-023의 상용화 위험)을 색 하나로 막을 수 있다. iOS 시안과 같은 규칙이다.
- 토큰을 CSS 변수로 바꾸는 것은 ADR-066 Revisit When이 미리 적어 둔 경로다. 클래스 이름을 유지해 화면 코드는 거의 그대로다.

## Consequences

- 셸(`Shell.tsx`)을 바꾸면 모든 화면이 함께 바뀐다. ADR-110 작업(#245·#250)이 같은 파일을 고치므로 그 PR이 머지된 뒤에 셸을 바꾼다.
- 주황 사용처 약 60곳을 의미별로 다시 칠한다. 의미를 잘못 분류하면 경고가 덜 눈에 띌 수 있어 화면별로 확인한다.
- 테마 전환은 토큰 이름은 그대로지만 값이 런타임에 바뀐다. 하드코딩한 hex(차트 어댑터 등 약 40곳)는 토큰 함수로 옮겨야 테마를 따른다.
  옮기기 전까지 그 부분은 드라큘라 색으로 남는다.
- 라이트 테마가 생기면 `color-scheme`·스크롤바·차트 격자 같은 다크 가정이 깨질 수 있다. 테마별로 화면 점검이 필요하다.
- 상태 알약의 "실행 중 전략·미체결" 숫자는 쿼리 두 개가 더 필요하다. 데이터가 없으면 숫자 없이 모드 배지만 보인다.

## Revisit When

- 레일 8개도 많다는 사용 데이터가 나오면(특정 항목 클릭률이 매우 낮음) — 탐색을 홈 안으로 넣는 등 더 줄인다.
- 지표가 7개를 넘는 화면이 생기거나 1280px 이하 비중이 커지면 — "+N 지표" 접기를 실제로 켜고 우선순위를 화면별로 정한다.
- 테마 이용률이 드라큘라에 쏠리면 — 테마 수를 줄여 점검 비용을 낮춘다.
