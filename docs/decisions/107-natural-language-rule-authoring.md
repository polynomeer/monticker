# ADR-107: 전략 작성은 노코드 블록 + 자연어 번역으로 — AI는 기존 규칙 형식으로 번역만 하고, 사용자 코드는 실행하지 않는다 (검토 중)

## Status
Proposed — 구현 전 결정 초안이다. 법률 자문([legal-review-brief.md §2-13](../legal-review-brief.md#2-13-이용자의-말을-ai가-매매-규칙으로-번역하는-것이-투자자문에-해당하는가))과 사용자 인터뷰([user-interview-guide.md](../user-interview-guide.md)) 결과에 따라 Accepted로 올리거나 고쳐 쓴다. [ADR-105](105-target-user-and-core-loop-redefinition.md)가 Proposed인 동안에는 이 ADR도 Proposed로 둔다.

## Context

### 질문

퀀트 매매를 코딩 없이 제공할 수 있는가, 아니면 쉽게 코딩해서 돌릴 수 있게 돕는 쪽이 나은가.

### 지금 있는 것

- **Quant Lab 룰셋 빌더**: 블록 UI로 조건을 조합해 JSON 규칙 형식(entryRules, exitRules, positionSizing)으로 저장한다. 같은 규칙이 백테스트·포워드 테스트·신호에 그대로 쓰인다. 지표 계산은 평가 시점 이후 데이터를 보지 않는다([technical/quant-rule-engine.md](../technical/quant-rule-engine.md)). 한계는 **한 번에 한 종목**만 다룬다는 것이다([product.md](../product.md) 로드맵 표).
- **Watch Rule**: 이벤트·전략 신호 → 미리 정한 모의 주문([ADR-051](051-event-triggered-paper-orders.md), [077](077-watch-rule-signals-compound-daily-limit.md), [095](095-watch-rule-group-target-limit-equity-pct.md)). 모의계좌 전용.
- **조건부 주문**: 익절·손절·OCO, 실계좌([ADR-032](032-conditional-orders.md)).
- **AI 주문 제안**: AI는 방향과 근거만 내고 수량·가격을 정하지 않으며, 제출은 사용자가 기존 주문 폼에서 한다([ADR-036](036-ai-order-proposal.md)).

### 고려한 대안

| 대안 | 내용 | 판단 |
|------|------|------|
| A. 블록 노코드만 | 지금의 룰셋 빌더를 다듬는다 | 필요하지만 충분하지 않다. 블록 UI는 "삼성전자가 내일 5% 빠지면 절반 팔아" 같은 말을 옮기는 데 여러 단계가 든다 |
| **B. 자연어 → 기존 규칙 형식** | AI가 사용자 문장을 Quant Lab·Watch Rule·조건부 주문의 규칙 형식으로 번역하고, 사용자가 블록으로 확인·수정한다 | **채택** |
| C. 코딩 지원 (사용자 코드를 서버에서 실행) | 파이썬 편집기 + AI 코딩 도우미 + 서버 실행 | 기각 (아래 Reasons) |
| D. 주문 경로 API | 코딩하는 사용자는 자기 봇을 직접 돌리고, 주문만 monticker의 리스크 검사·킬 스위치·복기 기록을 거치게 한다 | 보류. 인터뷰에서 코딩하는 사용자 수요가 보이면 별도 ADR |

## Decision

1. **실행되는 표현은 기존 규칙 형식 하나다.** Quant Lab JSON 규칙, Watch Rule, 조건부 주문 외에 새로운 실행 경로를 만들지 않는다. 블록 UI는 그 형식의 편집기로 유지한다.
2. **자연어는 그 형식으로의 번역기다.** 흐름은 다음과 같다.
   ```
   사용자 문장
     → AI: 스키마가 강제된 구조화 출력(규칙 JSON 초안 + 되물을 질문 목록)
     → 서버: 결정적 검증 (스키마, 지원 지표·연산자, 값 범위, 종목 존재)
     → 화면: "이렇게 이해했습니다" 한국어 재진술 + 블록 표시
     → 사용자: 수정·확인
     → 저장 (이후는 손으로 만든 규칙과 똑같다)
   ```
   AI 출력이 검증을 통과하지 못하면 저장하지 않고, 실패 이유를 사용자에게 보여준다.
3. **AI는 번역만 하고 설계하지 않는다.**
   - 사용자 문장에 없는 조건·수치·종목·수량을 AI가 채우지 않는다. 빠진 값은 되묻는다(예: "'많이 빠지면'은 몇 %인가요?", "얼마나 팔까요?").
   - "수익 나는 전략 만들어 줘", "뭐 사면 돼?"처럼 판단을 맡기는 요청에는 규칙을 만들지 않고, 사용자 자신의 조건을 묻는 안내로 돌린다.
   - ADR-036의 "AI는 수량·가격을 정하지 않는다"와 같은 선이다.
4. **번역 결과가 바로 실계좌 주문이 되지 않는다.**
   - 모의 Watch Rule, Quant Lab 룰셋: 확인 후 저장.
   - 실계좌 조건부 주문: AI는 **기존 조건부 주문 폼의 초안**만 채운다. 제출은 사용자가 그 폼에서 하고, 리스크 검사·실시세 커버리지 검사([ADR-060](060-realtime-price-coverage-for-conditional-orders.md))를 그대로 거친다. ADR-036의 "승인 ≠ 제출" 패턴과 같다.
   - 실계좌 Watch Rule은 ADR-105·legal-review-brief §2-9의 결론이 나기 전까지 만들지 않는다. 이 ADR은 그 선을 옮기지 않는다.
5. **원문과 결과를 함께 남긴다.** 사용자 원문 문장, AI가 만든 초안, 사용자가 확인한 최종 규칙, 모델 식별자, 시각을 저장한다. 번역 오류로 분쟁이 생겼을 때 무엇을 확인받았는지 증명하기 위해서다.
6. **모델은 기본값(Haiku)으로 정하지 않고 번역 평가셋으로 고른다.** 대표 문장과 기대 규칙 쌍으로 평가셋을 만들고, 정확도·되묻기 적절성·비용을 비교해 고른다. AI 모델 선택 기준은 [tech-stack-decisions.md](../tech-stack-decisions.md) §11의 ADR 후보이기도 하다.
7. **사용자 코드를 서버에서 실행하지 않는다** (대안 C 기각). 주문 경로 API(대안 D)는 보류한다.
8. **범위 밖**: 규칙 형식을 여러 종목 단위(상위 N개 선택, 비중 배분, 정기 리밸런싱)로 넓히는 일은 별도 ADR로 결정한다. 이 ADR은 지금 형식으로 표현되는 것만 번역한다.

### 적용 순서

1. 자연어 → 모의 Watch Rule, 실계좌 조건부 주문 폼 초안 (ADR-105 핵심 사용자용)
2. 자연어 → Quant Lab 룰셋 (2차 사용자용)
3. (별도 ADR) 다종목 규칙 형식, 그 다음 자연어 번역 대상에 추가

## Reasons

- **핵심 사용자와 맞는다.** ADR-105의 직장인 투자자는 코드를 원하지 않는다. "밤에 정해 두기"의 문턱을 말 한 문장으로 낮추는 것이 이 방향의 핵심 가치다.
- **새 실행 경로가 없다.** AI 출력은 기존 규칙 형식이므로 백테스트·포워드 테스트·리스크 검사·킬 스위치·실시세 출처 검사(ADR-055)를 그대로 통과한다. 안전장치를 새로 만들거나 우회할 일이 없다.
- **검증이 결정적이다.** AI가 무엇을 내든 서버 검증과 사용자 확인 두 겹을 거친다. AI의 오류는 "잘못된 초안"으로 끝나고 "잘못된 주문"이 되지 않는다.
- **대안 C를 기각한 이유:**
  - 사용자 코드를 서버에서 돌리려면 격리 실행 환경, 자원 제한, 실행 비용 부담이 생긴다. 시세 데이터를 사용자 코드에 넘기는 재배포 라이선스 문제도 생긴다.
  - 사용자 코드가 실계좌 주문에 닿으면 리스크 검사가 막아야 할 입력의 종류가 무한히 넓어진다.
  - 코딩하는 사용자는 KIS·키움 API와 범용 AI 코딩 도구로 이미 무료로 같은 일을 한다. 이 시장에서는 QuantConnect 같은 전문 플랫폼과 경쟁하게 된다.
  - ADR-105의 핵심 사용자와 거리가 멀다.
- **국내에서 비어 있는 자리다.** 자연어 조건검색(유진AI)과 규칙 실행 도구(키움 등)는 있지만, 둘을 증권사 구분 없이 안전장치와 함께 이은 서비스는 찾지 못했다.

## Consequences

- **번역 오류 위험이 생긴다.** 확인 화면이 있어도 사용자가 재진술을 대충 읽고 확인할 수 있다. 실계좌 쪽을 폼 초안까지로 묶은 것이 이 위험을 줄이는 장치다.
- **AI 호출 비용과 지연이 규칙 작성 흐름에 들어온다.** 평가셋을 만들고 모델이 바뀔 때마다 다시 돌려야 한다.
- **국외 이전 범위가 넓어진다.** 지금 Anthropic에 보내는 것은 뉴스·공시·가격 데이터다(legal-review-brief §1-5). 이 기능은 **사용자가 직접 쓴 문장**을 보낸다. 보유 수량·금액 같은 개인 정보가 섞일 수 있다.
- **"번역만" 원칙은 프롬프트만으로 지켜지지 않는다.** 출력 스키마(빈 값은 되묻기 목록으로만), 서버 검증(사용자 문장에 없는 수치가 들어왔는지 대조), 평가셋의 거절 사례로 함께 지켜야 한다.
- 블록 UI와 자연어 입력 두 길을 함께 유지해야 한다.

## Revisit When

- 법률 자문 §2-13이 "번역만 해도 투자자문에 해당한다" 또는 "확인 절차로는 부족하다"고 답할 때.
- 사용자 인터뷰에서 규칙을 미리 정하는 습관 자체가 드물다는 결과가 나올 때(ADR-105 H2). 그러면 문턱을 낮추는 것보다 다른 문제가 먼저다.
- 평가셋에서 번역 정확도가 실사용에 못 미칠 때 — 자연어를 "블록 UI 채우기 도우미"로만 축소한다.
- 코딩하는 사용자의 수요가 확인될 때 — 대안 D(주문 경로 API)를 별도 ADR로 검토한다.
