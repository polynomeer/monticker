# ADR-037: 종목 커뮤니티 댓글 — 키워드+AI 하이브리드 권유 필터

## Status
Accepted

## Context

`docs/product.md`/`docs/engineering-backlog.md` §8 "소셜 커뮤니티"는 지금까지 "검토 중 — 우선순위 낮음"이라는 한 줄 외에 아무 스펙도 없었다(ADR-023에서도 낮은 우선순위로만 언급). 사용자와 스펙을 논의해 아래로 범위를 좁혔다.

**핵심 컨셉**: 완전히 새로운 SNS형 커뮤니티나 트레이더 소셜 그래프(팔로우/프로필)가 아니라, 이 제품의 "이벤트 중심" 정체성과 가장 자연스럽게 맞닿는 **종목별 토론 게시판**으로 시작한다. 댓글은 종목 전체에 대해 자유롭게 쓸 수 있고, 선택적으로 특정 이벤트(`stock_events`)를 태그할 수 있다 — 이벤트가 없는 날에도 종목 자체에 대한 대화가 가능해야 하므로, "이벤트별 댓글"로만 좁히지 않는다.

**규제 리스크**: Strategy Market(ADR-035)에서 이미 다뤘던 유사투자자문업 규제 우려가 여기서도 그대로 적용된다 — 오히려 여기가 더 직접적이다. 사용자가 자유롭게 종목에 대해 글을 쓸 수 있는 공간은 "이 종목 사세요/파세요" 같은 노골적인 매수·매도 권유가 쏟아질 위험이 실질적으로 크다. `docs/legal-review-brief.md`가 이미 AI 요약(§1-5)과 Strategy Market(§2-2), AI 주문 제안(§2-7, ADR-036)의 투자자문업 이슈를 다루고 있으므로, 이 기능도 같은 우려선상에 있다는 걸 사람이 검토해야 한다.

기존에 이미 있는 `wallet.EmotionTag`(자기 거래에 다는 사적 감정 태그: FOMO/확신/불안 등, `backend/api/.../wallet/domain/EmotionTag.kt`)는 완전히 사적이고 자기성찰용이라 이 기능과 무관하다 — 재사용 대상이 아니라 "감정 태그 ≠ 투자 조언" 원칙의 기존 선례로만 참고했다.

## Decision

### 도메인 모델

신규 모듈 `com.monticker.api.community`:

- `StockComment`: `id`, `stockId`, `eventId`(nullable — 선택적 이벤트 태그), `userId`, `content`, `createdAt`, `deletedAt`(nullable, 작성자 본인 삭제)
- `CommentReport`: `id`, `commentId`, `reporterId`, `reason`, `createdAt` — 동일 사용자의 중복 신고는 유니크 제약으로 막는다.
- 대댓글/스레드 없음(플랫 목록만) — 필요해지면 나중에 확장.

### API — `/api/stocks/{stockId}/comments`

- `POST` `{content, eventId?}` — 모더레이션 통과해야 저장.
- `GET ?eventId=&page=&size=` — 목록 조회.
- `DELETE /{id}` — 작성자 본인만.
- `POST /{id}/report {reason}` — 신고 저장만 한다. 자동 숨김이나 처리 워크플로우는 범위 밖 — 관리자가 나중에 직접 DB를 조회해 대응하는 걸 전제로 한다(1라운드).

### 모더레이션 — 키워드 1차 + AI 2차 하이브리드, fail-closed

1. **키워드 1차**: "사세요/파세요/지금 매수/매수 추천/가즈아" 류의 명백한 권유 표현은 외부 호출 없이 즉시 차단(빠르고 무료).
2. **AI 2차**: 키워드에 걸리지 않은 나머지는 `OrderProposalService`(ADR-036)와 같은 방식으로 Claude Haiku에게 구조화 판정을 요청한다(`{"isRecommendation": bool, "reason": "..."}`). "오를 것 같다/실적이 좋다" 같은 의견·전망은 권유가 아니고, "지금 사라/매수 추천"처럼 직접적인 행동 권유만 차단하도록 프롬프트에 명시한다.
3. **fail-closed**: 이 필터는 컴플라이언스 게이트이므로, `StockSummaryService`처럼 실패 시 조용히 통과시키지 않는다. AI 미설정이거나 호출/파싱이 실패하면 게시 자체를 막는다("지금은 댓글을 게시할 수 없습니다. 잠시 후 다시 시도해주세요") — 가용성보다 규제 리스크 회피를 우선한다.
4. `AnthropicClient`/`AnthropicConfig`는 `common.config`에 있어 `ai` 모듈에 의존하지 않고 `community` 모듈이 직접 사용한다 — 두 모듈이 같은 보일러플레이트(Claude 호출+JSON 파싱)를 각자 작게 중복하는 것이, `community`가 `ai`(이미 여러 모듈에 의존)에 얹혀 전이 의존을 늘리는 것보다 낫다고 판단했다.
5. 댓글 작성에 `@RateLimited`(분당 5개)를 적용해 스팸/AI 호출 남용을 막는다.

### 프론트

종목 상세 페이지에 "커뮤니티" 탭 신설. 댓글 목록 + 작성 폼(+ 최근 이벤트 태그 선택 드롭다운) + 본인 글 삭제 + 신고 버튼.

## Reasons

- 종목 전체 게시판(이벤트 선택적 연결)은 이벤트가 뜸한 종목에서도 커뮤니티가 죽지 않게 하면서, 이벤트 타임라인과의 연결점도 유지한다.
- 키워드 1차 필터는 명백한 케이스를 무료·즉시 차단해 AI 호출 비용/지연을 줄이고, AI 2차 판정은 키워드로 못 잡는 애매한 표현("좋아 보이네요 들어가볼까" 같은 완곡한 권유)까지 커버한다.
- fail-closed는 이 기능 전체의 존속을 가르는 규제 리스크 앞에서 가용성보다 안전을 우선하는, 이 세션에서 반복적으로 지켜온 원칙(AI 가드레일 = "제안만, 자동실행 금지"와 같은 결의 선택)과 일관된다.

## Consequences

- AI 2차 판정 비용/지연이 댓글 작성마다 발생한다(키워드로 걸러지지 않는 대부분의 정상 댓글에도 호출됨) — 트래픽이 커지면 키워드 룰을 더 정교화하거나 캐싱을 고려해야 할 수 있다.
- 신고 기능이 저장만 하고 처리 워크플로우(자동 숨김 임계치, 관리자 대시보드)가 없어, 신고가 쌓여도 사람이 직접 확인하기 전까진 아무 조치도 자동으로 일어나지 않는다.
- 투자자문업 규제 검토가 이 기능에 대해 아직 이뤄지지 않았다 — `docs/human-action-items.md`에 반영 필요.

## Revisit When

- 트래픽이 늘어 AI 호출 비용/지연이 부담될 때 — 키워드 룰 강화, 결과 캐싱, 또는 배치 판정 검토.
- 신고가 실제로 쌓이기 시작할 때 — 최소한의 자동 숨김 임계치(예: N건 이상 신고 시 임시 비공개) 또는 관리자 조회 화면 추가.
- 법률 검토 완료 후 — 키워드 리스트·AI 프롬프트의 판정 기준 조정이 필요할 수 있다.
- 대댓글/스레드가 필요해질 만큼 참여가 늘어날 때.
