# ADR-099: 관심 분야는 홈·알림 화면의 정렬·강조 신호로만 쓰고, 끌 수 있는 스위치를 계정에 둔다

## Status
Accepted

## Context

ADR-089로 온보딩의 관심 분야(9종 enum)·사용 방식(3종)을 `user_preferences`(V86)에 저장했지만 아무 기능에도 쓰지 않았다.
docs/design-rollout-plan.md §6 /onboarding 행은 "홈·알림 우선순위 반영은 후속"으로 남겨 두었고, ADR-089의 Revisit When이
"규칙 정의, 섹터 enum과 `stocks.sector` 매핑"을 요구했다.

제약:

- **정보를 숨기면 안 된다.** 관심 분야 밖의 급등락·공시를 덜 보여 주면 사용자가 모르는 사이 시장 정보가 걸러진다.
- **종목 추천처럼 읽히면 안 된다.** "관심 분야 종목"을 올리는 것이 "이 종목을 보라/사라"로 읽히지 않게, 사용자가 고른 분야 기준이라는 점과 끌 수 있다는 점이 화면에 보여야 한다.
- **푸시 발송량·방해 금지 시간은 건드리지 않는다.** 전달 정책은 api·worker가 같은 사례표(`backend/contracts/notification-delivery-policy.json`, ADR-093)로 맞춰 두었다. 관심 분야로 발송을 늘리거나 줄이면 그 표와 두 앱 구현을 모두 바꿔야 하고, "관심 밖이라 알림이 안 왔다"는 사고가 생긴다.
- `stocks.sector`는 KRX 업종 대분류(예: 전기전자, 의약품, 금융업, 운수장비)와 시드의 세부 업종(반도체, 바이오)이 섞인 자유 문자열이다. 관심 분야 enum과 1:1로 맞는 값이 없다.

고려한 대안:

1. **서버가 관심 분야로 이벤트·섹터 API 응답을 재정렬/가중** — 공개 API(비로그인 캐시 30초)에 사용자별 분기가 생겨 캐시가 깨지고, 매핑이 서버·웹 두 곳에 생긴다.
2. **알림 발송 우선순위(관심 분야는 즉시, 나머지는 묶음)** — 위 전달 정책 제약에 걸린다. 기각.
3. **관심 분야 밖 항목 접기/숨기기** — 정보 은닉. 기각.
4. **웹에서 이미 그리는 항목 안에서만 순서를 바꾸고 표시를 붙이며, 끌 수 있게** — 채택.

## Decision

1. **매핑은 한 곳**: `apps/web/src/lib/interestSectors.ts`의 `INTEREST_SECTOR_KEYWORDS`.
   업종 문자열을 정규화(공백·가운뎃점·하이픈 제거, 소문자)한 뒤 키워드를 **포함**하면 해당한다.

   | 관심 분야 | 업종 키워드 |
   |---|---|
   | 반도체 `SEMICONDUCTOR` | 반도체, 전기전자 |
   | 2차전지 `SECONDARY_BATTERY` | 2차전지, 이차전지, 배터리, 전기전자, 화학 |
   | 인터넷·플랫폼 `INTERNET_PLATFORM` | 인터넷, 플랫폼, 소프트웨어, it서비스, 서비스업 |
   | 바이오 `BIO` | 바이오, 제약, 의약품, 의료 |
   | 금융 `FINANCE` | 금융, 은행, 증권, 보험 |
   | 자동차 `AUTOMOTIVE` | 자동차, 운수장비, 운송장비 |
   | 조선·방산 `SHIPBUILDING_DEFENSE` | 조선, 방산, 방위, 항공, 기계, 운수장비, 운송장비 |
   | 배당주 `DIVIDEND`, ETF `ETF` | 없음 — 업종이 아니라 업종 문자열로 알 수 없다. 정렬에 영향 없음 |

   대분류는 여러 분야에 겹친다(전기전자 = 반도체·2차전지). 정렬 신호일 뿐이라 겹침을 허용한다.
   이벤트에는 업종이 없으므로 **이벤트 유형은 매핑하지 않는다** — 이벤트는 그 종목의 업종(시세 응답 `sector`)으로 판단한다.
   사용 방식(`usageStyle`)은 어디에도 쓰지 않는다(근거 없는 가중을 만들지 않는다).
2. **정렬 규칙**: `interestFirst(items, sectorOf, interests, enabled)` — 관심 분야 항목을 앞으로, 나머지를 뒤로 두는 **안정 분할**.
   원소를 빼거나 더하지 않는다. 관심 분야가 없거나 스위치가 꺼져 있으면 입력 순서 그대로.
3. **홈**
   - 섹터 히트맵: 기존 규칙(시세 있는 섹터·종목 수 순)으로 **24개를 먼저 자른 뒤** 그 안에서 관심 분야 먼저. 그리는 섹터 집합은 스위치와 상관없이 같다. 관심 섹터는 보라 테두리 + "관심" 글자.
   - 이벤트 피드(지금 움직이는 종목/공시/뉴스): 탭 필터 후 **최신 12건을 먼저 자른 뒤** 그 안에서 관심 분야 종목 먼저 + "관심" 표시. 각 그룹 안은 최신순 그대로.
   - 두 패널 머리에 "관심 분야 순" 칩(관심 분야가 있을 때만). 비로그인·관심 분야 없음이면 아무것도 바뀌지 않고 칩도 없다.
4. **스위치 저장**: V95 `user_preferences.interest_ordering BOOLEAN NOT NULL DEFAULT TRUE`.
   `PATCH /api/users/me/preferences { interestOrdering }`(빠지면 400)가 이 값만 바꾼다(행이 없으면 빈 선택으로 만든다).
   `PUT`(관심 분야·사용 방식 저장)은 이 컬럼을 덮어쓰지 않는다. `GET` 응답에 `interestOrdering`이 추가된다.
   유효 상태 = 관심 분야 ≥ 1 **그리고** 스위치 켜짐 → "관심 분야가 있으면 기본 켜짐".
5. **알림(보수적)**: `/alerts` 알림 이력에 **"관심 분야" 필터 칩**만 추가한다(관심 분야가 있을 때만 보임, 기본 필터는 "전체" 그대로).
   스위치가 켜져 있으면 관심 분야 종목 알림 행에 "관심" 표시를 붙인다. 목록 순서(최신순)는 바꾸지 않는다.
   푸시·이메일 발송, 방해 금지 시간, 알림 설정, `notification-delivery-policy.json`, worker는 **변경 없음** — 서버의 전달 경로는 `interest_ordering`·`interest_sectors`를 읽지 않는다.
6. **설정**: `/settings/interests`(설정 메뉴 "관심 분야")에서 관심 분야·사용 방식을 바꾸고(PUT) 스위치를 켜고 끈다(PATCH). 온보딩 흐름은 그대로이고 문구만 "준비 중"에서 실제 동작 설명으로 바꿨다.

## Reasons

- 이미 그리기로 한 항목 안에서만 순서를 바꾸므로 "관심 분야 때문에 안 보이게 된 정보"가 구조적으로 생기지 않는다(테스트로 고정: 개수·집합 보존, 안정성).
- 공개 API와 서버 캐시를 사용자별로 쪼개지 않는다. 매핑이 웹 한 파일에만 있어 바꾸기 쉽다.
- 발송 경로를 건드리지 않아 ADR-082/093의 전달 정책 불변식과 api·worker 공유 사례표가 그대로 유지된다.
- 스위치를 계정에 두면 기기를 바꿔도 같은 화면이고, 끄면 정확히 이전 화면이 된다.

## Consequences

- 업종 키워드 포함 매칭은 근사다. "화학"은 2차전지 소재가 아닌 화학주도, "기계"는 조선·방산이 아닌 기계주도 포함한다. 업종 대분류만 있는 데이터에서는 피할 수 없다 — 화면에 "업종명으로 맞춘다"고 밝혔다.
- 이벤트 피드의 관심 표시는 시세 응답(`/api/screener/quotes`)의 `sector`에 기대므로, 시세가 오기 전 잠깐은 최신순으로 보였다가 재정렬된다.
- 배당주·ETF를 고른 사용자는 스위치가 켜져 있어도 화면 변화가 없다(설정 화면에 그렇게 적었다).
- 알림 이력 필터는 화면이 받은 최근 50건 안에서만 거른다(서버 검색 조건 아님).
- 관심 분야 목록이 세 곳(Kotlin enum, V86 CHECK, 웹 `INTEREST_SECTORS`)에 있다는 ADR-089의 부담은 그대로다. 분야를 추가하면 키워드도 이 파일에 추가한다.

## Revisit When

- `stocks`에 표준 업종 코드(예: KRX 업종 코드, GICS)가 생기면 키워드 매칭을 코드 매핑으로 바꾼다.
- 배당·ETF를 판별할 데이터(배당수익률, 상품 유형)가 생기면 DIVIDEND·ETF 매핑을 채운다.
- 관심 분야로 푸시를 고르거나 묶고 싶다는 요구가 생기면 — 전달 정책 사례표와 api·worker를 함께 바꾸는 새 ADR로 다룬다.
- 사용 방식(`usageStyle`)을 화면 구성(예: 기본 탭)에 쓰기로 할 때.
