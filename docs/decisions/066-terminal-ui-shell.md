# ADR-066: 웹 UI를 트레이딩 터미널 셸로 전환 — 다크 전용, 상단 바 + 아이콘 레일

## Status
Accepted

## Context

웹(apps/web)의 화면 골격은 상단 가로 NavBar(드롭다운 2개: 투자 도구·내 자산)와 가운데 정렬된 `max-w-6xl` 본문이었다.
화면이 30개를 넘으면서 세 가지가 맞지 않았다.

- **정보 밀도.** 종목 상세에서 주문·호가·차트·이벤트를 함께 봐야 하는데, 카드가 세로로 쌓여 스크롤이 길어졌다.
- **내비게이션.** 2단 드롭다운에 숨은 화면(체결 엔진, 리스크, 정산)은 찾기 어려웠다. 실전투자와 모의투자가 같은 모양이라 지금 어느 계좌를 보고 있는지 화면만으로 구분되지 않았다.
- **테마 이중 유지.** 라이트/다크 두 벌의 클래스(`text-gray-900 dark:text-dracula-fg`)를 모든 컴포넌트에 달았다. 그런데 차트·호가처럼 가장 중요한 화면은 사실상 다크 기준으로만 다듬어져 있었다.

디자인 시안(2026-10, Kraken Pro의 화면 구성을 참고하고 색은 기존 Dracula 팔레트 유지)을 승인받아 앱 전체에 적용하기로 했다. 고려한 대안:

1. **기존 NavBar 유지, 페이지 내부만 패널화.** 변경이 작다. 그러나 내비게이션 문제와 계좌 구분 문제가 그대로 남는다.
2. **라우트 그룹 레이아웃(`app/(terminal)/layout.tsx`)에서 셸을 그림.** 셸이 한 곳에 모인다. 그런데 상단 바의 시세 스트립(종목 현재가, 계좌 요약)이 페이지마다 다르다. 결국 레이아웃↔페이지 사이에 컨텍스트나 포털이 필요하고, 라우트 디렉터리도 전부 옮겨야 한다.
3. **페이지가 `TerminalPage`로 스스로를 감쌈** — 채택.

## Decision

- 공통 키트 `apps/web/src/components/terminal/`을 둔다. 구성은 다음과 같다.
  - `TerminalPage`: 상단 바(로고·제목 또는 종목 선택·시세 스트립·계좌 칩·알림·계정) + 왼쪽 아이콘 레일 + 본문.
  - `Panel`: 탭 헤더와 설정·확대 아이콘이 달린 패널.
  - 입력·버튼·표·작은 차트, 시안의 아이콘 세트.

  각 앱 화면은 `<TerminalPage title stats account>`로 감싼다. 로그인·약관·온보딩은 셸 없이 그린다.
- 루트 레이아웃은 더 이상 NavBar를 그리지 않는다.
- **다크 전용.** `ThemeProvider`에 `forcedTheme="dark"`를 둔다. 새로 쓰는 화면에는 `dark:` 변형을 달지 않는다.
- **상승/하락 색은 CSS 변수.** `--mt-up`/`--mt-down`을 쓰고, Tailwind에서는 `text-up`·`bg-down`처럼 쓴다. 사용자 차트 테마(`themeStore`)가 이 값을 바꾼다. 그래서 차트뿐 아니라 호가·등락률·매수 버튼까지 같은 색을 따른다.
- **실계좌 화면 표식.** 실거래 경로 화면은 `account={{ kind: "live" }}`로 상단 계좌 칩을 주황으로 바꾸고, `LiveBadge`와 경고 배너를 반드시 단다.
- **시안에만 있는 기능은 화면만 먼저 넣는다.** 백엔드가 없는 요소는 실제처럼 보이는 숫자를 지어내지 않는다. 대신 `—`·빈 상태·비활성 컨트롤로 두고, 패널에 "준비 중" 표식(`preview`)을 단다. 구현 계획은 [design-rollout-plan.md](../design-rollout-plan.md)에서 추적한다.
- 숫자는 `.num`(시스템 고정폭 스택 + tabular-nums)으로 정렬한다. CSP `font-src 'self'` 때문에 웹폰트 모노를 쓰지 않는다. 본문은 기존 self-host Pretendard를 그대로 쓴다.

## Reasons

- 페이지가 자기 상단 바 내용을 직접 넘기므로 레이아웃↔페이지 상태 공유 장치가 필요 없다. 라우트를 옮기지 않아도 된다.
- 아이콘 레일은 모든 영역을 한 번의 클릭 거리에 둔다. 활성 판정은 가장 긴 경로 일치로 한다(`/quant-lab/market`은 퀀트랩이 아니라 전략 마켓).
- 다크 전용으로 클래스 두 벌을 없애면 화면당 스타일 코드가 줄고, 시안과의 1:1 대응이 쉬워진다.
- 실계좌 표식을 셸 수준에 두면 화면을 새로 만들 때 빠뜨리기 어렵다. 실주문 화면 혼동은 상용화 단계의 실제 위험이다([ADR-023](023-commercialization-pivot.md)).

## Consequences

- 라이트 테마와 "시스템 설정 따르기"가 사라진다. 설정 화면의 테마 선택은 다크만 동작하고, 나머지는 계획서 항목이다.
- 기존 `Card`·`PageLayout`·`NavBar`·`ThemeToggle`은 전환이 끝나면 쓰이지 않는다. 잔존 사용처를 확인한 뒤 지운다.
- 페이지마다 `TerminalPage`를 감싸는 반복이 생긴다. 셸 동작을 바꾸면 모든 페이지가 같이 바뀌는 대신, 페이지별 예외(셸 없는 화면)는 각 페이지가 정한다.
- 고정폭 숫자 폰트가 OS마다 다르게 보인다(SF Mono / Consolas 등).
- "준비 중" 표식이 붙은 패널이 여럿 생긴다. 계획서의 우선순위대로 하나씩 실데이터로 바꿔야 하고, 표식이 오래 남으면 미완성 제품처럼 보인다.

## Revisit When

- 라이트 테마 요구가 실사용자에게서 반복해서 나올 때. 그때는 토큰을 CSS 변수로 바꾸고 테마별 값을 두는 방식으로 되돌린다.
- 사용자가 패널 배치를 저장하는 "레이아웃 편집"을 구현할 때. 패널 상태를 페이지 밖(스토어·서버)으로 옮겨야 하므로 셸 구조를 다시 본다.
- 모바일 웹 비중이 커져 아이콘 레일이 좁은 화면에서 부담이 될 때. 하단 탭 바로 바꾸는 것을 검토한다.
