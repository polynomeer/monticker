# ADR-106: 여러 증권 계좌 통합 — 데이터 출처를 단계로 나누고, 스크래핑은 쓰지 않는다 (검토 중)

## Status
Proposed — 기획안([account-aggregation-plan.md](../account-aggregation-plan.md))과 함께 쓴 결정 초안이다. 1단계는 사용자 결정만 있으면 시작할 수 있다. 2·3단계는 법률 자문([legal-review-brief.md §2-10·§2-12](../legal-review-brief.md))이 나와야 시작한다.

## Context

이용자의 여러 증권사 계좌를 한곳에 모아 보여주는 기능(포트폴리오 트래커)을 검토했다. 지금 있는 것은 다음과 같다.

- 증권사 연동(KIS·토스, BYOK)은 **주문용**이다. 사용자당 활성 계좌 1개, 국내 원화 잔고만 조회하고 저장하지 않는다.
- 포트폴리오·원장·분석은 **모의계좌 전용**이다(ADR-012·013·091).

"모든 증권 계좌"를 덮는 길은 넷이다.

1. **이용자 입력** — 수동 입력, 증권사에서 내려받은 거래내역 파일(CSV·엑셀) 업로드
2. **증권사 Open API(BYOK) 읽기 전용** — API를 여는 증권사만 된다(KIS·토스·키움 REST·LS 등). 증권사마다 클라이언트가 필요하다.
3. **마이데이터** — 본인신용정보관리업 허가를 직접 받거나, 허가 사업자·중계기관과 제휴한다. 금융투자 업권 표준 API(금투-001~004)가 계좌·예수금·거래내역·보유 상품(해외 포함)을 준다.
4. **스크래핑** — 이용자 아이디·비밀번호로 증권사 화면을 읽는다. 개정 신용정보법은 표준 API를 전제로 한다. 허가 없는 유사 서비스는 금지됐다.

제약도 있다.

- ADR-105는 핵심 루프를 "밤 계획 → 낮 자동 대응 → 저녁 복기"로 두고 포트폴리오·세금 최적화를 내렸다.
- legal-review-brief §2-10은 "다른 금융기관 정보와의 통합은 계획하지 않는다"고 설명해 왔다.

## Decision

1. **데이터 출처를 단계로 나눈다.** 1단계는 이용자 입력(수동·파일), 2단계는 Open API 읽기 전용 다계좌, 3단계는 마이데이터(제휴 또는 허가)다. 각 단계는 앞 단계를 대체하지 않고 **출처를 하나 더한다.** 계좌마다 출처를 기록한다.
2. **스크래핑은 쓰지 않는다.** 법적 위험이 있고, 이용자 금융 비밀번호를 보관해야 하기 때문이다.
3. **데이터 모델은 처음부터 마이데이터 금융투자 API 모양에 맞춘다.** 구성은 계좌, 거래 원장, 보유 스냅샷, 상품, 통화다. 1·2단계 데이터가 3단계로 그대로 이어진다. **보유는 거래 원장으로 계산하고, 증권사·마이데이터가 주는 스냅샷과 대사한다.**
4. **주문용 연동과 조회용 계좌를 분리한다.** 실계좌 리스크 검사·조건부 주문은 지금처럼 주문용 계좌의 실시간 잔고를 쓴다. 통합 포트폴리오는 표시·알림·복기용이다. 실거래 데이터 출처 불변식(ADR-055)에 섞지 않는다.
5. **ADR-105 루프의 재료로 둔다.** 우선순위는 통합 보유 → 보유 기준 피드·알림 → 계획 밖 매매 순이다. 수익률·배당·배분·환율은 그다음이다. 세금은 최적화가 아니라 추정만 한다.
6. **조회용 연동에는 주문 권한이 있는 키를 받지 않는 것을 원칙으로 한다.** 읽기 전용 권한이 없는 증권사는 그 사실을 화면에 밝히고 동의를 받는다.

## Reasons

- 단계를 나누면 자문 없이 할 수 있는 1단계로 가치를 먼저 검증한다. 2·3단계는 자문 결과에 따라 고르거나 건너뛸 수 있다.
- "모든 증권사"를 실제로 덮는 합법 경로는 마이데이터뿐이다. Open API를 주지 않는 증권사가 있어 BYOK는 일부만 된다. 표준 API 모양으로 저장해 두면 나중에 갈아타는 비용이 작다.
- 원장 기준 + 스냅샷 대사로 하면 출처마다 다른 신뢰도(파일 누락, API 지연)를 같은 방식으로 다룬다.
- 주문 경로와 분리하면 실계좌 안전장치(리스크 한도·킬 스위치)의 근거 데이터가 출처가 섞인 데이터로 오염되지 않는다.

## Consequences

- 계좌·원장·스냅샷·상품 테이블이 새로 생긴다. 모의계좌용 테이블과 한동안 공존한다. 모의계좌는 읽기 어댑터로 붙인다.
- 증권사 내보내기 파일 형식마다 어댑터를 유지해야 한다. 증권사가 형식을 바꾸면 깨진다 — 실제 파일 골든 테스트로 지킨다.
- 2단계에서는 이용자 키를 여럿 보관한다. BYOK 보안 요구(암호화·해지 시 삭제·이상 접근 감지)의 무게가 커진다.
- legal-review-brief의 "통합은 계획하지 않는다" 설명이 바뀌었다(§2-12 추가). 자문 결과에 따라 2단계가 막힐 수 있다.

## Revisit When

- §2-10·§2-12 자문 결과가 나오면 2·3단계를 할지 정하고, 이 ADR을 Accepted로 올리거나 고친다.
- ADR-105 인터뷰에서 "증권 계좌가 여럿이고 한곳에서 보고 싶다"는 수요가 약하면 1단계 이후를 멈춘다.
- 마이데이터 제휴 비용·조건을 알아본 뒤 3단계에서 허가와 제휴 중 하나를 고른다.
- 증권사들이 읽기 전용 Open API 권한을 제공하기 시작하면 6번 원칙을 적용하는 방식을 다시 본다.
