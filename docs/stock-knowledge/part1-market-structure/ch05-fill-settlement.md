# 5장. 체결과 청산

> **핵심 한 줄**: 체결(Fill)은 "주문이 이루어졌다"는 사건이고, 정산(Settlement)은 "돈과 주식이 실제로 이동했다"는 완료다.

---

## 5.1 체결 (Fill) / 부분체결 (Partial Fill)

### 전체 체결 (Full Fill)

주문한 수량 **전부**가 단번에 체결된 경우.

```
매수 주문: 100주 @ 55,000원
→ 100주 전량 체결 → FILLED
```

### 부분 체결 (Partial Fill)

주문한 수량 중 **일부**만 체결된 경우. 나머지는 계속 호가창에 대기합니다.

```
매수 주문: 100주 @ 55,000원
→ 50주 체결 (상대방이 50주만 있었음) → PARTIALLY_FILLED
→ 잔량 50주는 여전히 호가창에 대기
```

> monticker의 `FillEvent`는 체결 수량(`filledQty`), 체결가(`fillPrice`), 잔여 수량(`remainingQty`)을 포함합니다.

---

## 5.2 미체결 (Unfilled) / 잔량

지정가 주문이 상대방을 찾지 못하면 **미체결(Open)** 상태로 호가창에 남습니다.

- 장 마감 시 미체결 지정가 주문은 자동 취소
- 단, 조건부 지정가는 마감 시 시장가로 전환
- IOC 주문은 즉시 미체결 잔량 취소

```
09:10 매수 지정가 100주 @ 50,000원 접수
15:29 → 여전히 미체결
15:30 → 장 마감 → 자동 취소 (EXPIRED)
```

---

## 5.3 평균 체결가 (Average Fill Price, VWAP Fill)

하나의 주문이 여러 번 분할 체결될 때 **실제 평균 단가**를 계산해야 합니다.

```
1차: 30주 @ 55,100원
2차: 50주 @ 55,000원
3차: 20주 @ 54,900원

평균 체결가 = (30×55,100 + 50×55,000 + 20×54,900) ÷ 100
           = (1,653,000 + 2,750,000 + 1,098,000) ÷ 100
           = 5,501,000 ÷ 100
           = 55,010원
```

수익률 계산, P&L(손익) 계산에서 **항상 평균 체결가를 기준**으로 해야 합니다.

## 5.4 슬리피지 (Slippage)와 시장충격 (Market Impact)

### 슬리피지 (Slippage)

**의도한 가격과 실제 체결가의 차이**.

```
의도한 매수가: 55,000원
실제 체결가:   55,150원
슬리피지:      +150원 (0.27%)
```

원인:
- 시장가 주문 → 호가창의 다음 단계까지 체결되는 경우
- 주문 제출과 체결 사이 가격 변동 (지연, latency)
- 유동성 부족

### 시장충격 (Market Impact)

**내 주문 자체가 가격을 움직이는 효과**.

```
1,000주 시장가 매수 주문 → 
  Ask 1호가 55,000원에 300주 체결
  Ask 2호가 55,100원에 400주 체결
  Ask 3호가 55,300원에 300주 체결
→ 내 주문 때문에 가격이 상승함
```

대규모 기관이 포지션을 조용히 청산하려는 이유: 자신의 매도 주문이 가격 하락을 부르기 때문.

> **백테스팅에서 중요**: 백테스트에서 슬리피지를 무시하면 실제 트레이딩보다 훨씬 좋은 결과가 나옵니다.  
> monticker 백테스트는 `slippageBps` (basis points) 파라미터로 슬리피지를 모델링합니다.

## 5.5 T+2 결제 — 실물 이동 없는 장부 정산

체결(거래)과 결제(정산)는 다릅니다.

| 단계 | 내용 |
|------|------|
| **Trade (T일)** | 매수/매도 쌍방이 체결에 동의. 주식과 현금은 아직 이동 안 함 |
| **Clearing** | 거래 확인, 수량·금액 검증. KSDCP(한국예탁결제원) 개입 |
| **Settlement (T+2)** | 실제 주식과 현금의 계좌 간 이동 완료 |

### 왜 이 구조인가?

- 하루에 수백만 건의 거래를 건마다 즉시 정산하면 비효율적
- 네팅(Netting): 같은 종목을 오늘 사고판 경우, 차액만 정산
- 오류 발견 시 T+2 이내에 취소 처리 가능

### 페이퍼 트레이딩에서의 T+2

monticker 모의투자는 실제와 동일하게 T+2 영업일 후 정산을 처리합니다.

```kotlin
// 체결 시
paperAccount.reserveSettlement(trade)  // T일: 미정산 상태

// T+2 영업일 후 스케줄러 실행
paperSettlementService.settle(tradeDate)  // 지갑에 실제 반영
```

## 5.6 증거금 (Margin)

### 위탁증거금 (Commission Deposit)

주문 제출 시 증권사에 예탁해야 하는 최소 금액.

```
위탁증거금율: 40% (종목마다 다름)
100만원 주식 매수 주문 시 → 40만원 이상 잔고 필요
```

### 신용거래 증거금 (Margin Trading)

보유한 돈 이상의 주식을 빌린 돈으로 사는 레버리지 거래.

```
계좌 잔고: 100만원
신용 한도: 200만원 추가 (3배 레버리지)
→ 총 300만원어치 주식 매수 가능
→ 10% 하락 시 실제 손실 = 30만원 (자기 돈의 30%)
```

monticker는 **신용거래를 지원하지 않습니다**. 학습 목적의 모의투자는 레버리지 없는 현금 기반으로만 운영합니다.

---

## 요약

```
체결(Fill) = 주문이 상대방과 매칭되어 거래 확정
부분체결 = 일부만 체결, 잔량은 대기 또는 취소
슬리피지 = 의도가격 vs 실제 체결가 차이
T+2 = 체결 후 2영업일에 실물 정산
증거금 = 주문 시 필요한 최소 담보금
```
