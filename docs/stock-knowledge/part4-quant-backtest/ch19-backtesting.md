# 19장. 백테스팅 (Backtesting)

> **핵심 한 줄**: 백테스트는 전략의 과거 성과를 시뮬레이션하지만, 과거가 미래를 보장하지 않는다.

---

## 19.1 백테스트의 목적과 한계

### 목적

- 전략의 **역사적 성과** 검증
- 파라미터 최적화
- 리스크 지표 추정 (MDD, 변동성)
- 실거래 전 아이디어 검증

### 구조

```
역사 데이터 (가격, 재무, 지표)
    │
    ▼
규칙 적용 (진입/청산 조건)
    │
    ▼
주문 시뮬레이션 (체결가, 수수료)
    │
    ▼
성과 계산 (수익률, MDD, Sharpe 등)
```

### 핵심 한계

**"백테스트에서 좋았던 전략이 실전에서 반드시 좋은 것은 아니다."**

이를 이해하는 것이 퀀트 투자의 출발점입니다.

---

## 19.2 Look-ahead Bias (미래참조 편향)

**가장 치명적인 백테스트 오류**. 그 시점에 알 수 없었던 미래 정보를 사용하는 것.

### 흔한 사례

```
잘못된 예:
  재무 데이터 발표일: 2024년 3월 15일
  → 백테스트에서 2024년 1월 1일부터 이 데이터 사용
  → 실제로는 2024년 1월에 이 정보를 알 수 없었음

올바른 예:
  발표일 이후인 2024년 3월 16일부터 데이터 사용
```

### 다른 형태들

- 종가로 매수 신호를 확인하고 **같은 날 종가**에 체결하는 경우
  - 현실: 종가를 보는 순간 이미 장이 끝남 → 다음 날 시가에 체결해야 함
- 연간 이익 데이터를 **분기 발표 전부터** 사용
- 지수 리밸런싱 날짜 정보를 미리 아는 경우

---

## 19.3 Survivorship Bias (생존자 편향)

**현재 존재하는 종목만으로 백테스트하면 이미 실패한 종목의 데이터가 빠진다.**

```
2010년 KOSPI 종목 1,500개 중
→ 2024년까지 살아남은 종목: 900개
→ 상장폐지/합병된 종목: 600개

생존자 편향 백테스트: 1,500 → 900개만 분석 (나쁜 결과 제외)
→ 결과가 실제보다 좋게 나옴
```

### 해결책

- 백테스트 당시 **실제로 존재했던** 종목 universe 사용
- 상장폐지 종목 데이터 포함
- Point-in-time 데이터베이스 구축

---

## 19.4 과최적화 (Overfitting) / 커브 피팅

**특정 역사 구간에 너무 잘 맞춰진 파라미터를 찾아내는 것.**

```
RSI(14)로 백테스트:
  연 수익률: 15%, Sharpe: 1.2

RSI(9)로 최적화:
  연 수익률: 35%, Sharpe: 2.1  ← 과최적화 의심

→ 이 파라미터가 우연히 과거 데이터에 잘 맞는 것일 수 있음
→ 미래 데이터에는 작동 안 할 가능성 높음
```

### 과최적화 징후

- 파라미터를 조금만 바꿔도 성과가 급락
- 백테스트 기간이 짧음 (2~3년)
- 지나치게 많은 규칙과 파라미터
- In-sample과 Out-of-sample 성과 차이가 큼

---

## 19.5 Walk-forward Optimization

과최적화를 방지하는 가장 현실적인 방법.

```
전체 데이터: 2010 ~ 2024

1. In-sample (훈련): 2010 ~ 2015 → 파라미터 최적화
2. Out-of-sample (검증): 2016 ~ 2017 → 성과 확인

다음 단계:
1. In-sample: 2012 ~ 2017 → 파라미터 재최적화
2. Out-of-sample: 2018 ~ 2019 → 성과 확인

반복...
```

각 Out-of-sample 구간의 성과를 이어 붙이면 **실전에 가까운 성과** 추정이 가능합니다.

---

## 19.6 Monte Carlo 시뮬레이션

역사적 수익률 순서를 **무작위로 섞어** 수천 번 시뮬레이션.

```
실제 거래 수익률 순서:
+2%, -1%, +3%, -5%, +1%...

Monte Carlo: 순서를 무작위 섞어 1,000번 시뮬레이션
→ 결과 분포에서 최악의 5% 케이스 = 리스크 추정
```

목적:
- MDD의 분포 (최악/평균/최선) 추정
- 운(순서)과 실력 분리

---

## 19.7 Out-of-sample Test

```
In-sample  (개발/최적화): 2010 ~ 2020
Out-of-sample (검증):    2021 ~ 2024

원칙: Out-of-sample은 전략 완성 후 단 한 번만 사용
```

Out-of-sample을 반복 사용하면 결국 그 구간에 맞춰지게 됩니다.

## 요약

```
백테스트 = 과거 데이터로 전략 시뮬레이션
Look-ahead Bias = 미래 정보 사용 (가장 흔한 오류)
Survivorship Bias = 실패 종목 제외 (결과 과대 추정)
Overfitting = 과거에만 맞는 파라미터 (미래에 안 됨)
Walk-forward = 시간 순서를 지킨 In/Out-of-sample 검증
Monte Carlo = 순서 무작위화로 리스크 분포 추정
```
